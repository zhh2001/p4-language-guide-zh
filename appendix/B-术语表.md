# 附录 B · 术语表（中英对照）

本表按英文词条排序，忽略大小写和标点。代码标识符保留原样，同一个词涉及语言、架构或控制协议时，在说明中注明适用范围。

P4_16 语言术语依据 v1.2.5 规范，P4Runtime 术语依据 v1.4.1 规范。简短定义用于查阅，接口限制与实验条件以链接的正文为准。

## A

| 英文            | 中文           | 说明                                                                                                                     |
| --------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Accept          | 接受解析       | Parser 的内置终态 `accept`，表示本轮解析正常结束。后续是否转发由处理逻辑决定                                             |
| Action          | 动作           | 用 `action` 定义的一组数据平面操作，可由表选择执行，也可在控制块中直接调用                                               |
| Action data     | 动作数据       | 表项或默认动作提供的动作无方向参数值，可来自控制平面或 P4 源码                                                           |
| Action profile  | 动作配置       | 通过成员间接引用动作及其数据，让多个表项复用同一成员。不是报文复制机制                                                   |
| Action selector | 动作选择器     | 在动作成员组中选择一个成员执行，常用于 ECMP 或链路聚合。与 Action profile 的区别见[第 16 章](../docs/16-PSA与TNA简介.md) |
| Annotation      | 注解           | 以 `@` 开头的附加说明，如 `@name`、`@atomic`。含义与适用位置由语言、架构或目标规定                                       |
| Apply           | 应用／执行     | 调用 Parser、Control 或表实例的 `apply` 方法。它与编译期的实例化不同                                                     |
| Arbitration     | 仲裁           | P4Runtime 服务端按设备与角色确定客户端的主备地位。不代替控制器之间的共识或状态同步                                       |
| Architecture    | 架构／体系结构 | 规定可编程块、块间接口、元数据和相关行为。实际执行这些行为的是目标实现                                                   |
| ASIC            | 专用集成电路   | 为特定用途设计的集成电路。其中只有部分器件提供可由 P4 编程的数据平面                                                     |
| Atomicity       | 原子性         | 保证一组操作不以中间状态被其他相关操作观察到。保证范围需结合语言规则与目标实现核对                                       |

## B

| 英文                          | 中文           | 说明                                                                                                             |
| ----------------------------- | -------------- | ---------------------------------------------------------------------------------------------------------------- |
| Base (V1Model hash parameter) | 基值           | V1Model `hash` 参数 `base`，表示结果范围的起点。范围还取决于 `max`，见[第 12 章](../docs/12-外部对象Extern.md)   |
| Bit string                    | 位串           | 按位表示的值。`bit<W>` 是宽度为 W 的无符号定长位串                                                               |
| BMv2                          | 行为模型第二版 | Behavioral Model v2，提供软件报文处理模型的框架。`simple_switch`、`psa_switch` 是其中不同的目标程序              |
| BQE                           | 缓冲排队引擎   | Buffering Queuing Engine。PSA 中位于 egress 之后的固定功能块，接口与行为见[第 16 章](../docs/16-PSA与TNA简介.md) |

## C

| 英文                  | 中文           | 说明                                                                                 |
| --------------------- | -------------- | ------------------------------------------------------------------------------------ |
| Checksum              | 校验和         | 根据规定的数据范围计算的差错检测值。例如 IPv4 报头校验和只覆盖 IPv4 报头             |
| Clone                 | 克隆／报文复制 | 按架构规定生成报文副本。副本采用哪个时刻的报文字节、保留哪些元数据，须分别核对       |
| Constructor parameter | 构造参数       | 实例化时绑定的参数，在编译期确定。不能用当前报文的运行时字段作为构造实参             |
| Control block         | 控制块         | 用 `control` 定义的数据平面处理块，组织查表、动作及 extern 调用等操作                |
| Control plane         | 控制平面       | 计算、维护策略并配置数据平面的逻辑，如路由计算和表项更新。不同于 P4 的 Control block |
| Core library          | 核心库         | `core.p4`，提供 P4_16 的基础声明。接口说明见[附录 A](A-核心库core.p4解析.md)         |
| Counter               | 计数器         | 记录报文数、字节数等规定的计数量。更新位置和字节长度口径需按接口与实现确认           |
| CPU port              | CPU 端口       | 目标中通往处理器或控制软件的逻辑报文接口。编号与接入方式由目标约定，不必对应物理端口 |

## D

| 英文           | 中文     | 说明                                                                                      |
| -------------- | -------- | ----------------------------------------------------------------------------------------- |
| Data plane     | 数据平面 | 执行报文解析、查表、修改、复制、转发等处理的逻辑，可由硬件或软件实现                      |
| Default action | 默认动作 | 表未命中时执行的动作。无键表也执行默认动作，执行默认动作不等于命中表项                    |
| Deparser       | 反解析器 | 按程序指定的顺序序列化报头。通常由架构指定的 `control` 实现，没有独立的 `deparser` 关键字 |
| Digest         | 摘要     | 数据平面将程序选定的数据报告给控制平面的机制。不是完整报文，也不会自动建立学习表项        |
| Direction      | 参数方向 | `in`、`out`、`inout` 的参数传递约定。无方向参数是另一种情形，规则取决于声明种类           |
| Drop           | 丢弃     | 使报文不再沿相应正常输出路径转发。生效时机和对副本的影响由架构规定                        |

## E

| 英文                | 中文               | 说明                                                                                                                     |
| ------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| ECMP                | 等价多路径         | Equal-Cost Multipath，在多个等代价下一跳之间分配流量，哈希是常见的选择方法                                               |
| Egress              | 出方向／出向处理   | 面向输出侧的处理阶段。具体可编程块、元数据与处理顺序由架构规定                                                           |
| Election ID         | 选举 ID            | P4Runtime 仲裁使用的 128 位无符号值，在同一设备、同一角色的范围内比较。规则见[第 15 章](../docs/15-P4Runtime控制平面.md) |
| `emit`              | 输出／写出         | `packet_out` 的方法，按有效位与调用顺序追加报头数据。不自动重算校验和                                                    |
| Entry (table entry) | 表项               | 表中的匹配条件及对应动作或成员引用等数据。默认表项有单独的表示与操作规则                                                 |
| `enum`              | 枚举               | 由命名成员组成的类型。P4_16 还支持具有显式底层位宽的可序列化枚举                                                         |
| Error               | 错误标识           | P4 的 `error` 类型及其成员，如 `error.PacketTooShort`。可由解析操作或 `verify` 报告                                      |
| `extern`            | 外部对象／外部函数 | 用 P4 声明接口，具体实现由编译器和目标提供，用于访问核心库或架构规定的功能                                               |
| `extract`           | 提取               | `packet_in` 的方法，将输入位流读入报头。成功后使报头有效并推进游标                                                       |

## F

| 英文                       | 中文       | 说明                                                                         |
| -------------------------- | ---------- | ---------------------------------------------------------------------------- |
| Fan-in / Fan-out           | 扇入／扇出 | 某节点汇入或分出的分支数量。分支代表信号、路径还是其他对象，需结合上下文判断 |
| Flow                       | 流         | 按选定字段或条件归类的报文集合，可由五元组或自定义键标识                     |
| FQN (Fully Qualified Name) | 完全限定名 | 包含所需层级或作用域信息的名称。控制平面对象的名称应以实际接口描述为准       |

## H

| 英文         | 中文       | 说明                                                                                                             |
| ------------ | ---------- | ---------------------------------------------------------------------------------------------------------------- |
| Hash         | 哈希       | 将数据映射为哈希值，常用于分桶或成员选择。不同输入可能产生相同结果                                               |
| Header       | 报头       | P4 的 `header` 类型描述字段布局，并具有独立的有效位                                                              |
| Header stack | 报头栈     | 同一报头或报头联合体类型的固定容量有序集合，如 `H[N]`。容量、元素有效性和 Parser 的 `nextIndex` 应分别理解       |
| Header union | 报头联合体 | `header_union`，一组最多只有一个成员有效的报头，与普通 `struct` 不同                                             |
| Hit          | 命中       | 查表找到匹配的普通表项，表应用结果的 `hit` 为 `true`                                                             |
| Hop Limit    | 跳数限制   | IPv6 字段，每个转发节点将其减 1。字段定义见 [RFC 8200 §3](https://www.rfc-editor.org/rfc/rfc8200.html#section-3) |

| Instantiation                | 实例化           | 在编译期建立 Parser、Control、Package 或可实例化的 extern 的实例并绑定构造参数。不同于运行时调用 `apply` 或 extern 方法     |
| INT                          | 带内网络遥测     | In-band Network Telemetry，由数据平面采集并报告网络状态。报文携带与报告方式有不同模式                                       |

| Invalid header               | 无效报头         | 有效位为 `false` 的报头，不能依赖其字段值。对它执行 `emit` 不输出报头内容                                                   |

## P

| -------------------- | ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Table                | 匹配-动作表        | 规定匹配键、允许的动作及其他属性，应用时查找表项并执行选定动作或默认动作                                                                            |
| Target               | 目标／目标实现     | 能够执行 P4 程序的硬件或软件报文处理系统，提供具体能力与资源限制                                                                                    |
| TCAM                 | 三态内容寻址存储器 | 支持按位匹配 0、1 或不关心的一类硬件存储资源，常用于掩码查找                                                                                        |
| Ternary              | 三态匹配／三元匹配 | 用值与掩码表示逐位匹配条件，典型写法为 `value &&& mask`。不是三元组                                                                                 |
| TM (Traffic Manager) | 流量管理器         | 承担缓冲、排队、调度等功能的模块，具体组织方式和可配置接口取决于目标与架构                                                                          |
| TNA                  | Tofino 原生架构    | Tofino Native Architecture，面向 Tofino 的元数据、可编程块与 extern 接口。公开工具链及部署条件见[第 16 章](../docs/16-PSA与TNA简介.md)              |
| Token bucket         | 令牌桶             | 按设定速率补充令牌、按报文或字节消耗令牌的机制，可用于计量或流量整形等功能                                                                          |
| TTL (Time to Live)   | 生存时间           | IPv4 字段，用于限制报文存活时间，转发时递减。IPv6 对应字段称为 Hop Limit，见 [RFC 791 §3.1](https://www.rfc-editor.org/rfc/rfc791.html#section-3.1) |
| Tuple                | 元组               | 有序、可含不同类型元素的组合，如 `tuple<bit<32>, bool>`，不同于 Ternary 匹配                                                                        |
