# 示例 01 · Hello P4

本例在 BMv2 `simple_switch` 上执行报文反射：从哪个端口收到，就从哪个端口原样发回。程序不转发 h1 与 h2 之间的流量，也不生成 ICMP Echo Reply。

源码说明见 [第 3 章](../../docs/03-第一个P4程序.md)。

## 拓扑与依赖

```text
h1 (10.0.0.1/24) ── 端口 1 ── s1 ── 端口 2 ── h2 (10.0.0.2/24)
                           Hello P4
```

两台主机使用独立的 network namespace，经 veth 与 BMv2 相连。主机内接口名均为 `eth0`，命名空间与交换机侧接口名在每次运行时生成。脚本不使用 Mininet。

需要 `p4c-bm2-ss`、`simple_switch`、`ip`，以及支持 `os.setns` 的 Linux Python 3.12+。自动验证只用 Python 标准库，手工抓包另需 `tcpdump`；安装说明见 [第 1 章](../../docs/01-环境搭建.md)。

## 编译与运行

以下命令从**仓库根目录**执行：

```bash
bash examples/01-hello/build.sh
sudo bash examples/01-hello/run.sh
```

`build.sh` 默认在示例目录中生成 `hello.json` 和 `hello.p4info.txtpb`，也可用第一个参数指定输出目录。本例没有表，无需下发表项；P4Info 仅供查看，不用于此次运行。

`run.sh` 每次重新编译当前源码到临时目录，随后启动 BMv2 并自动验证；默认测试结束就退出并清理资源。

## 验证标准

[verify.py](./verify.py)分别从两台主机发送 60、128、1514 字节的以太帧（不含 FCS），检查原主机收到一份逐字节一致的反射帧，且观察窗口内另一主机没有收到测试帧。它排除本机发包记录，并用随机标识区分测试帧与背景流量。

六项检查通过后输出 `PASS：两个端口的 Hello P4 反射验证完成`；超时、内容不一致、错误端口或重复副本都会导致失败。检查不是性能测试，观察窗口详见第 3 章。

## 手工观察

```bash
sudo bash examples/01-hello/run.sh --keep
```

验证通过后保留拓扑，脚本打印可直接复制的抓包、ping 和重新验证命令，以及临时日志路径。先在另一个终端启动接收方向的 ARP 抓包，再发 ping；结束时先停止抓包，再在运行脚本的终端按 Ctrl+C。

h1 的 ARP 请求会被反射，h2 收不到它，邻居解析无法完成。仅凭 ping 不通或看到本机发送的请求，不能证明程序正确；自动检查提供了逐字节比较的依据。

正常结束、报错、SIGINT 或 SIGTERM 时，脚本只清理本次创建的资源。编译产物和日志所在临时目录也会删除，需要保留日志时应在退出前复制。

实测版本：p4c `1.2.5.10`、BMv2 `1.15.0-2bdd0b7b`、Python `3.12.3`，运行环境为 Ubuntu 24.04 / WSL2。
