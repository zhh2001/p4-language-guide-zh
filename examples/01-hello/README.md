# 示例 01 · Hello P4

本例在 BMv2 `simple_switch` 上执行报文反射：从哪个端口收到，就从哪个端口原样发回。Parser 直接结束解析，Ingress 将入端口写入 `egress_spec`，BMv2 保留并输出报文原有的字节。

源码说明见 [第 3 章](../../docs/03-第一个P4程序.md)。

## 拓扑与依赖

```text
h1 (10.0.0.1/24) ── 端口 1 ── s1 ── 端口 2 ── h2 (10.0.0.2/24)
                           Hello P4
```

两台主机使用独立的 network namespace，经 veth 与 BMv2 相连。主机内接口名均为 `eth0`，`run.sh` 在每次运行时生成命名空间与交换机侧接口名，并直接创建这组网络资源。

需要 `p4c-bm2-ss`、`simple_switch`、`ip`，以及支持 `os.setns` 的 Linux Python 3.12+。自动验证使用 Python 标准库，手工观察另需 `tcpdump` 和 `ping`。安装说明见 [第 1 章](../../docs/01-环境搭建.md)。

## 编译与运行

以下命令从**仓库根目录**执行，分别用于单独编译和运行完整实验：

```bash
bash examples/01-hello/build.sh
sudo bash examples/01-hello/run.sh
```

`build.sh` 默认在示例目录中生成 `hello.json` 和 `hello.p4info.txtpb`，也可用第一个参数指定输出目录。BMv2 加载 `hello.json`，程序直接根据入端口选择输出。`hello.p4info.txtpb` 供查看控制平面接口描述。

`run.sh` 自动将当前源码编译到临时目录，随后创建拓扑、启动 BMv2 并调用 `verify.py`。默认验证通过后退出并清理资源，编译、启动或验证失败时返回非零状态。

## 验证标准

[verify.py](./verify.py)分别从两台主机发送 60、128、1514 字节的以太帧（不含 FCS），使用广播目的 MAC、实验用 EtherType `0x88b5` 和随机标识。每次发送后，检查原主机收到一份逐字节一致的反射帧，并确认另一主机在观察窗口内没有收到该帧。验证程序排除本机发包记录与背景流量。

每帧最多等待 3 秒，收到反射后继续观察 0.3 秒，检查重复帧或另一端口上的副本。六项检查通过后输出 `PASS：两个端口的 Hello P4 反射验证完成`。超时、内容不一致、错误端口或重复副本都会使验证失败。

## 手工观察

```bash
sudo bash examples/01-hello/run.sh --keep
```

验证通过后，脚本保持运行并打印抓包、ping 和重新验证命令，以及临时日志路径。在第二个终端执行打印的抓包命令，再在第三个终端执行 ping 命令。抓包参数 `-Q in` 选择主机接口的接收方向，观察由交换机返回的 ARP 请求。

抓包应看到 h1 发出的 ARP 请求返回 h1。h2 收不到该请求，h1 无法获得 `10.0.0.2` 的 MAC 地址，ping 停留在邻居解析阶段。观察结束后，先停止抓包，再在运行脚本的终端按 Ctrl+C。

正常结束、报错、SIGINT 或 SIGTERM 时，脚本只清理本次创建的资源。编译产物和日志所在临时目录也会删除，需要保留日志时应在退出前复制。

实测版本：p4c `1.2.5.10`、BMv2 `1.15.0-2bdd0b7b`、Python `3.12.3`，运行环境为 Ubuntu 24.04 / WSL2。
