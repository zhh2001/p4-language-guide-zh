# 示例 05 · ECMP 等价多路径

本例将目的 IPv4 前缀映射到一个 ECMP 组，再对 TCP/UDP 五元组计算 CRC32，选择组内下一跳。选中下一跳后改写源、目的 MAC，TTL 减 1，并更新 IPv4 报头校验和。

程序使用 V1Model，`hash` 接口见[第 12 章](../../docs/12-外部对象Extern.md#127-hash)，转发流水线见[第 11 章](../../docs/11-V1Model架构.md)。BMv2 是软件交换机，本例验证分流功能，不据此作出线速或吞吐量保证。

## 拓扑与实验范围

```text
                      端口 2 ── nh1（接收端）
                     /
h1 ── 端口 1 ── s1
                     \
                      端口 3 ── nh2（接收端）
```

| 节点 | IPv4 地址     | MAC 地址            | BMv2 端口 |
| ---- | ------------- | ------------------- | --------- |
| h1   | `10.0.1.1/24` | `00:00:00:00:00:01` | 1         |
| nh1  | `10.0.2.2/24` | `00:00:00:00:00:02` | 2         |
| nh2  | `10.0.2.3/24` | `00:00:00:00:00:03` | 3         |

每个节点是独立的 network namespace，主机侧接口名为 `eth0`，经 veth 连接 BMv2。脚本直接创建这些资源，不调用 Mininet。命名空间与交换机侧接口名称由脚本生成。

h1 的默认网关为 `10.0.1.254`，永久邻居项将其映射到 `00:00:00:01:00:00`。交换机不回应 ARP 或发给网关的 ping。nh1、nh2 模拟两个下一跳接收端，实验没有配置它们的后续转发、回程路由或共同目的主机。测试目的地址 `10.0.2.10` 不属于任何主机，验证的是报文到达哪个下一跳，不是到该地址的端到端连通性。

自动验证使用原始以太帧，直接指定网关 MAC。h1 的 Linux 路由与邻居项供手工使用普通 IP 工具时选取下一跳，不能仅凭原始帧验证成功就认定 Linux 路由或动态 ARP 已被验证。

## 两张表如何选路

| 表                           | 匹配键                    | 动作                                        |
| ---------------------------- | ------------------------- | ------------------------------------------- |
| `MyIngress.ipv4_lpm`         | 目的 IPv4，最长前缀匹配   | 设置组 ID、组大小并计算组内索引             |
| `MyIngress.ecmp_group_to_nh` | 组 ID、组内索引，精确匹配 | 写入下一跳 MAC、出端口 MAC 与端口，TTL 减 1 |

两张表的默认动作都固定为 `drop()`，也允许安装显式丢弃表项。第一张表执行 `drop` 后立即退出 Ingress，避免后续动作重新设置出端口而覆盖丢弃决定。组大小为 0 时也会直接丢弃。V1Model 的 `hash` 在 `max=0` 时返回 `base`，不能将这一结果解释为“空组可以使用索引 0”。

正常情况下，设五元组的 CRC32 值为 H，组大小为 N，则组内索引为 `H % N`。本例 `base=0`，默认 N=2，索引为 0 或 1。第二张表须为该组配置所有可达索引，缺少某个索引时，对应报文会命中默认丢弃动作，不会自动换用其他下一跳。N 不必是 2 的幂，但配置仍受表容量限制，本例组表总容量为 1024 项。

[runtime/s1-commands.txt](./runtime/s1-commands.txt)先安装两个下一跳，再安装引用它们的路由：

```text
table_add MyIngress.ecmp_group_to_nh MyIngress.set_nh 1 0 => 00:00:00:00:00:02 00:00:00:01:00:01 2
table_add MyIngress.ecmp_group_to_nh MyIngress.set_nh 1 1 => 00:00:00:00:00:03 00:00:00:01:00:02 3
table_add MyIngress.ipv4_lpm MyIngress.set_ecmp_group 10.0.2.0/24 => 1 2
```

这里的“等价”由配置者确定。P4 程序不会计算路径代价、检测链路存活或自动维护路由。

## 哈希能保证什么

在哈希算法、输入字段、组大小和索引映射都不变时，相同五元组会选择同一下一跳。负载内容、TCP 序号、IPv4 identification 和 TTL 不参与本例哈希。该性质减少了由逐包分流引入的乱序，但不能保证整条网络路径上绝不乱序。

不同流可以发生哈希碰撞，也不保证任意样本都均分到两个出口。即便两边流数相等，各流的报文数、字节数或速率也可能不同，链路负载未必相等。CRC32 用于分桶，不是唯一流标识或密码学哈希。

改变 N 或索引到下一跳的映射可能迁移已有流。本例没有保存流状态，不能承诺扩容、故障或重配置期间保持原有落点。两个方向分别计算五元组哈希，也不保证选择对称路径。

## 输入检查

Parser 只处理无 VLAN、IHL 为 5、未分片的 IPv4 报文，检查版本和 IPv4 总长度。总长度不得小于 20，也不得超过实际输入中 Ethernet 报头之后的字节数。解析错误、IPv4 报头校验和错误、TTL 为 0 或 1，以及非 IPv4 报文均丢弃。

TCP 至少包含 20 字节固定报头，`dataOffset` 至少为 5，声明的报头长度不得超过 IP 负载。UDP 至少包含 8 字节报头，`length` 不得小于 8 或超过 IP 负载。TCP 选项保留在未解析负载中，UDP 长度小于 IP 负载时也不裁去多余字节。

非 TCP/UDP 协议的两个端口键固定为 0，实际只按源地址、目的地址和协议号区分。IPv4 首片和后续片全部拒绝，判断条件是 MF 为 1 或分片偏移不为 0。后续片通常不携带传输层报头，直接读取“端口”会把分片数据误当成哈希键，还可能让同一数据报的不同分片走不同路径。

程序不验证 TCP/UDP 校验和、TCP 选项内容或连接状态。转发只修改 MAC、TTL 和 IPv4 报头校验和，传输层伪首部不变，因此保留传输层校验和原值。IPv4 总长度以外的帧尾字节也会随 BMv2 未解析负载保留。完整路由器还需要本例未实现的 ARP、ICMP 错误报告、MTU 处理和路由维护等功能。

## 编译与 Thrift 实验

依赖 `p4c-bm2-ss`、`simple_switch`、`simple_switch_CLI`、`ip`、`timeout`，以及支持 `os.setns` 的 Linux Python 3.12+。数据平面验证只使用 Python 标准库，无需 hping3 或 Scapy。安装与检查方法见[第 1 章](../../docs/01-环境搭建.md)。

从**仓库根目录**执行：

```bash
bash examples/05-ecmp/build.sh
sudo bash examples/05-ecmp/run.sh
```

`build.sh` 默认在示例目录生成 `ecmp.json` 和 `ecmp.p4info.txtpb`，也可用第一个参数指定输出目录。`run.sh` 每次重新编译当前源码到临时目录，创建拓扑，确认本进程的 Thrift 服务就绪，再加载配置并验证。

配置文件只用于尚未配置的新实例。脚本先过滤整行注释与空行，避免 CLI 报错或重复执行上一条命令，再检查错误文本并读回两张表。不要直接将原文件重定向给 CLI 或重复加载。

Thrift 默认端口为 9090，已被占用时在创建拓扑前退出。可通过环境变量另选空闲端口：

```bash
sudo env P4_ECMP_THRIFT_PORT=9091 bash examples/05-ecmp/run.sh
```

## 自动验证

[verify.py](./verify.py)在三个命名空间中打开原始套接字，从 h1 发送带随机标识的报文，并检查实际输出。它排除本机发包记录，以及引用原始负载的 ICMP 错误报文，逐字节比较 MAC、TTL、IPv4 校验和与其余内容。

先执行 33 个用例：

| 检查内容                                      | 预期结果                          |
| --------------------------------------------- | --------------------------------- |
| 60、128、1514 字节 UDP 帧，TTL 2/255          | 正确改写 MAC、TTL 和 IPv4 校验和  |
| 改变源地址、目的地址、目的端口或协议          | 按相应哈希键选择下一跳            |
| ICMP 与其他 IP 协议                           | 两个端口键为 0，按参考 CRC32 选路 |
| TCP 选项、帧尾字节、错误 TCP 校验和           | 对应字节保持不变                  |
| TTL 0/1、无路由                               | 丢弃                              |
| 错误版本、IHL、IPv4/TCP/UDP 长度、IPv4 校验和 | 丢弃                              |
| IPv4 选项、首片、后续片、非 IPv4、VLAN        | 丢弃                              |

随后构造源端口为 10000～10499 的 500 条 TCP 流，每条发送两帧。两帧的五元组相同，TTL 分别为 64 和 63，TCP 序号、IPv4 identification 和负载标识分别随机生成。验证程序用 Python `zlib.crc32` 独立计算本机 BMv2 的预期落点，逐帧检查结果。组内索引依赖输入字段的拼接顺序和目标的算法实现，不能据此假定不同目标一定产生相同结果。

本机这组样本中，nh1、nh2 各接收 250 条流、500 帧。这是固定样本的实测结果，不是对任意流量的均分保证。脚本限速分批发送，避免将软件队列的突发丢包混入功能验证。边界用例收到预期输出后继续观察 0.2 秒，丢弃用例同样观察 0.2 秒。批量用例最多等待 3 秒，全部收齐后再观察 0.05 秒，检查重复副本与错误出口。帧长不含 FCS。

配置失败、报文缺失、字节不符、重复输出或选错端口都会返回非零状态。全部通过后输出：

```text
PASS：ECMP 选路、同流稳定性、报头改写和丢弃验证完成
```

## P4Runtime 配置方式

[runtime/ctrl.py](./runtime/ctrl.py)提供另一条可运行的配置流程。需要 `simple_switch_grpc`，以及可导入 `grpc`、`p4.v1`、`p4.config.v1` 的 Python 环境。依赖说明与旧版 protobuf 生成模块的兼容设置见[第 15 章](../../docs/15-P4Runtime控制平面.md#154-python-客户端环境)。

若 `python3` 已具备这些依赖：

```bash
sudo bash examples/05-ecmp/run.sh --p4runtime
```

需要使用虚拟环境或本机的旧模块兼容设置时，可显式指定解释器。例如，本机使用：

```bash
sudo env P4_ECMP_PYTHON="$HOME/p4dev-python-venv/bin/python" \
  PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION=python \
  bash examples/05-ecmp/run.sh --p4runtime
```

此模式启动 `simple_switch_grpc --no-p4`，使用本次交换机进程对应的设备 ID。gRPC 绑定 `127.0.0.1:50051`，可通过 `P4_ECMP_GRPC_PORT` 更改。Thrift 端口仍由 `P4_ECMP_THRIFT_PORT` 指定，两个端口须不同且可用。系统 `python3` 负责网络验证，`P4_ECMP_PYTHON` 只负责控制客户端。

客户端从 P4Info 按名称查找表、动作、匹配字段和参数的 ID，按声明位宽检查数值，并使用大端最短非空字节串编码。它保持仲裁流开放，确认获得对应设备和 election ID 的主控身份后才安装流水线。组内成员写入成功后，再以独立请求安装路由，避免依赖批量更新的执行顺序。

**安装使用 `VERIFY_AND_COMMIT`，会清除原有转发状态。** 客户端只用于本例新建的专用实例，不应将重新运行它当作普通重连。写入失败也不意味着已成功的更新自动回滚。

客户端遍历 `Read` 的全部响应，按字段 ID 和数值核对三条表项，再关闭仲裁流与连接并退出。退出后表项仍保留，`run.sh` 随后执行与 Thrift 模式相同的 1033 帧数据平面验证。独立调用客户端时，可通过 `--address`、`--device-id`、`--election-id`、`--p4info`、`--json` 指定参数，默认产物路径相对于示例目录，不依赖当前工作目录。

## 手工观察与清理

```bash
sudo bash examples/05-ecmp/run.sh --keep
# 也可组合使用 --p4runtime --keep
```

验证后保留拓扑，脚本打印实际命名空间、抓包命令和重新运行验证的命令。Thrift 模式还会打印 CLI 地址，可执行 `table_dump MyIngress.ipv4_lpm` 和 `table_dump MyIngress.ecmp_group_to_nh` 查看配置。

观察下一跳应抓取进入 nh1、nh2 的报文。Linux 接口 RX 总数可能包含 IPv6、ARP 等背景报文，不能直接当作测试流数或 ECMP 分流正确性的证据。

正常退出、报错、SIGINT 或 SIGTERM 时，脚本只停止自己启动的交换机，并删除本次创建的接口、命名空间和临时目录。`--keep` 模式下按 Ctrl+C 结束，手工启动的抓包程序应先停止。需要保留日志时，请在退出前复制脚本打印的临时目录。

## 练习

- 增加更具体的前缀，检查最长前缀匹配。再分别配置空组、缺失索引和显式丢弃表项，确认不会继续转发。
- 扩为四个不同下一跳时，除修改 N 和组表外，还须创建并接通新增端口与接收端，更新 MAC、路由及验证预期。四个索引映射到两个现有端口不等于四条独立路径。
- 比较 `action_selector` 的选组接口与手写哈希表。能否更高效取决于目标实现和资源映射，V1Model 接口本身不作这种保证。
- 研究成员增删时的流迁移，可比较模运算、固定桶间接映射和一致性哈希等方案。一致性哈希不必依赖每流寄存器，若另行保存流状态，则还需设计冲突处理、超时和故障后的迁移规则。

实测环境：Ubuntu 24.04 / WSL2，p4c `1.2.5.10`、BMv2 `1.15.0`、Python `3.12.3`。
