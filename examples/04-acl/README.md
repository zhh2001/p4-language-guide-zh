# 示例 04 · IPv4 五元组 ACL

本例先按源 IPv4、目的 IPv4、IP 协议号、源端口和目的端口查询 ACL，再对允许的报文执行静态二层转发。五个字段都采用 `ternary`（三元匹配），支持逐位掩码。这里的“三元”指匹配方式，与五元组中字段的数量无关。

程序使用 V1Model，演示规则优先级、默认动作和命中计数。匹配表与计数器的接口分别见[第 8 章](../../docs/08-匹配动作表.md)和[第 12 章](../../docs/12-外部对象Extern.md)。

## 拓扑与地址

```text
h1 ── 端口 1 ─┐
              │
h2 ── 端口 2 ─┤ s1（acl.p4）
              │
h3 ── 端口 3 ─┘
```

| 主机 | IPv4 地址     | MAC 地址            | BMv2 端口 |
| ---- | ------------- | ------------------- | --------- |
| h1   | `10.0.0.1/24` | `00:00:00:00:00:01` | 1         |
| h2   | `10.0.0.2/24` | `00:00:00:00:00:02` | 2         |
| h3   | `10.0.0.3/24` | `00:00:00:00:00:03` | 3         |

三台主机位于同一子网，各自运行在独立的 network namespace 中，通过 veth 连接 BMv2。脚本直接创建这些资源，不调用 Mininet。命名空间和交换机侧接口使用本次运行生成的名称，主机侧接口均为 `eth0`。

`run.sh` 为每台主机配置另外两台主机的永久邻居项，使主机直接使用目的 MAC 封装 IPv4 报文，再向 P4 的 `l2` 表下发目的 MAC 到端口的映射。Linux 邻居项负责主机发包时的地址解析，P4 表项决定交换机的输出端口。交换机的解析范围见下文，ARP 报文会被丢弃。

## ACL 策略与优先级

[runtime/s1-commands.txt](./runtime/s1-commands.txt)安装以下三条 ACL 规则。表中的 `*` 只表示该字段不受限制，实际 CLI 命令使用 `0&&&0`。

| CLI 优先级 | 源 IPv4  | 目的 IPv4   | 协议 | 源端口 | 目的端口 | 动作   |
| ---------- | -------- | ----------- | ---- | ------ | -------- | ------ |
| 5          | 10.0.0.3 | 10.0.0.2    | TCP  | 40000  | 22       | permit |
| 10         | 10.0.0.1 | 10.0.0.3    | *    | *      | *        | deny   |
| 20         | *        | 10.0.0.0/24 | TCP  | *      | 22       | deny   |

本例通过 **BMv2 Thrift CLI** 下发表项，优先级数值越小越先匹配。h3 使用源端口 40000 发往 h2 的 TCP 22 报文同时匹配优先级 5 和 20，最终执行 `permit`。将源端口改成 40001 后，只匹配优先级 20 的拒绝规则。固定源端口用于构造规则重叠，观察五个匹配键与优先级共同决定的结果。

命令采用 `value&&&mask` 语法，例如 `6&&&0xff` 精确匹配 TCP 协议号，`10.0.0.0&&&0xffffff00` 匹配对应的 `/24`。`permit` 和 `deny` 没有参数，命令中 `=>` 后的数字是优先级。这里采用 Thrift CLI 的优先级约定，P4Runtime 使用“大数值优先”，见[第 15 章](../../docs/15-P4Runtime控制平面.md)。

ACL 的 `const default_action` 固定为 `permit()`，仅在没有表项命中时执行。ACL 允许后继续查询 `l2` 表，目的 MAC 未命中时执行该表的默认 `drop()`。通过两张表的报文按输入帧原样转发，MAC、IPv4 字段和负载均保持不变。TTL 为 0 或 1 的报文也可转发，本例执行的是二层转发，[示例 03](../03-ipv4-router/README.md)中的路由转发才会递减 TTL。

规则按每个报文的当前五元组匹配。h1→h3 命中拒绝规则，h3→h1 的 ICMP 报文则按默认动作允许。h3 ping h1 时，Echo Request 可以到达 h1，h1 发出的 Echo Reply 在返回方向被拒绝，因此仍收不到应答。

## 输入检查与解析范围

Parser 只支持无 VLAN、IHL 为 5、未分片的 IPv4 报文。它检查版本号、IPv4 总长度下限及实际输入长度，再按协议号解析 TCP 或 UDP。解析错误、IPv4 报头校验和错误以及非 IPv4 报文都在查询 ACL 前丢弃。

- TCP 至少有 20 字节固定报头，`dataOffset` 至少为 5，且所声明的 TCP 报头不得超出 IP 负载。TCP 选项保留在未解析负载中，转发时位置和内容不变。
- UDP 至少有 8 字节报头，`length` 在 8 与 IP 负载长度之间。`length` 可以小于 IP 负载长度，多出的字节随输入帧保留。
- ICMP 及其他 IP 协议不提取端口，两个端口匹配键在 Parser 开始时初始化为 0。配置规则时用协议键区分这些协议，以及端口值恰好为 0 的 TCP/UDP 报文。
- MF 为 1 或分片偏移不为 0 时直接拒绝，包括首片。此检查在读取 TCP/UDP 报头前完成，后续分片的数据不会被当作端口读取。本例不维护分片状态或进行重组。

TCP/UDP 校验和、TCP 选项内容和连接状态不参与检查。通过 ACL 与 L2 查表的报文保留传输层校验和原值，IPv4 `totalLen` 以外的帧尾字节也随 BMv2 未解析负载保留。Parser 的错误处理见[第 6 章](../../docs/06-Parser解析器.md)。

## 编译与运行

依赖 `p4c-bm2-ss`、`simple_switch`、`simple_switch_CLI`、`ip`、`ping`、`timeout` 和 Linux Python 3.10+，手工抓包还需 `tcpdump`。验证脚本只使用 Python 标准库，安装说明见[第 1 章](../../docs/01-环境搭建.md)。

从**仓库根目录**执行：

```bash
bash examples/04-acl/build.sh
sudo bash examples/04-acl/run.sh
```

`build.sh` 用于单独编译，默认在示例目录生成 `acl.json` 和 `acl.p4info.txtpb`，也可用第一个参数指定输出目录。运行配置由 Thrift CLI 下发，生成的 P4Info 文件供查阅接口使用。

`run.sh` 包含编译步骤，每次将当前源码编译到临时目录，先用文件端口验证，再创建三主机拓扑进行实际 ping 检查。脚本为新实例加载一次配置，过滤整行注释和空行，检查 CLI 的错误输出，并读回两张表。手工加载时也需先过滤配置文件，本机 CLI 将 `#` 注释视为未知命令，空行会重复上一条命令。修改已有实例时应根据实际表项句柄操作。

实际拓扑的 Thrift 端口默认为 9090，被占用时脚本在创建拓扑前退出。可以另选空闲端口：

```bash
sudo env P4_ACL_THRIFT_PORT=9091 bash examples/04-acl/run.sh
```

## 自动验证

[verify.py](./verify.py)创建一个独立的 BMv2 文件端口实例，从 PCAP 输入测试帧，逐字节比对各端口输出，并读取计数器核对报文数和字节数。文件端口直接读写 PCAP，计数只来自这些测试帧。TCP 22 规则通过构造指定五元组的报文验证，无需运行 SSH 服务。该测试检查 ACL 的逐包决策，不建立 TCP 连接。

共执行 46 个用例：

| 检查内容                                           | 预期结果                      |
| -------------------------------------------------- | ----------------------------- |
| 重叠的允许、拒绝规则，更换源地址、目的地址或源端口 | 选择符合五元组及优先级的规则  |
| h1→h3 的 TCP、UDP、ICMP 和其他 IP 协议             | 均命中优先级 10 并丢弃        |
| TCP 80、UDP 22、ICMP、其他 IP 协议及反向报文       | 按默认动作允许                |
| 60、128、1514 字节帧，帧尾填充，TCP 选项，TTL 0/1  | 输出字节保持不变              |
| ACL 允许但目的 MAC 不在 L2 表中                    | 丢弃，仍计入所命中的 ACL 规则 |
| 错误 TCP 校验和                                    | 允许规则仍生效，保留原字节    |
| 错误版本、IHL、IPv4/TCP/UDP 长度、IPv4 校验和      | 在 ACL 前丢弃                 |
| IPv4 选项、首片、后续片、非 IPv4、VLAN、截短帧     | 在 ACL 前丢弃                 |

帧长不含 FCS。文件端口等待 3 秒再开始读入报文，脚本须在此之前完成配置，否则报错退出。配置后最多等待 10 秒，通过 BMv2 调试日志确认输入已读完且每帧完成发送或丢弃，再等待 0.3 秒读取 PCAP。等待时间用于完成这组功能检查，不作为性能测量结果。

也可以不创建主机拓扑，以普通用户独立运行文件端口验证：

```bash
bash examples/04-acl/build.sh /tmp/acl-build
python3 examples/04-acl/verify.py /tmp/acl-build/acl.json
```

文件端口实例使用系统分配的独立 Thrift 端口，结束时停止自己的 BMv2 并删除临时文件。添加 `--output-dir /tmp/acl-pcap-result` 可保留 PCAP 和日志，该目录必须尚不存在。

文件端口验证通过后，`run.sh` 在实际拓扑检查 h1 ping h2、h2 ping h3 成功，h1 ping h3 无应答。命令错误与预期的无应答分别处理，失败不会被忽略。全部通过后输出：

```text
PASS：ACL 规则、计数器及三主机允许/拒绝路径验证完成
```

## 计数器与手工观察

用以下命令保留拓扑，再另开终端，按脚本打印的地址连接 CLI：

```bash
sudo bash examples/04-acl/run.sh --keep
```

`acl_ctr` 是通过 `counters = acl_ctr` 绑定到 ACL 表的直接计数器。V1Model 在表项命中时自动更新对应计数，无需在动作里显式调用 `count()`。CLI 读取时使用**表项句柄**，应先从表的输出中确定句柄与规则的对应关系：

```text
table_dump MyIngress.acl
```

例如输出中的 `Dumping entry 0x2` 表示十进制句柄 2，此时可执行：

```text
counter_read MyIngress.acl_ctr 2
counter_read MyIngress.acl_miss 0
```

`acl_miss` 是独立的间接计数器，代码仅在 `acl.apply().hit` 为假时调用 `acl_miss.count(0)`。它统计执行默认动作的报文，与命中表项时更新的 `acl_ctr` 分别记录两条路径。

上述 46 个文件端口用例中，优先级 5、10、20 对应的直接计数器各为 **4 packets、512 bytes**，`acl_miss[0]` 为 **12 packets、2866 bytes**。另外 22 帧在 ACL 前丢弃，不更新这两种计数器。字节数按输入帧计，包括 Ethernet 报头和帧尾字节。ACL 允许后在 L2 表被丢弃的报文也会更新 ACL 计数，因此这些计数反映的是 ACL 查表结果。

实际三主机实例的计数包含脚本发出的 ping 和后续手工流量。观察一组报文时，可在发包前后各读一次计数器，用差值核对命中的规则和默认动作。

例如，从 h3 ping h1，同时在 h1 的 `eth0` 上分别用 `tcpdump -Q in` 和 `tcpdump -Q out` 抓取 ICMP：入方向应看到 Echo Request，出方向应看到主机生成的 Echo Reply，而 h3 收不到返回应答。对应地，`acl_miss[0]` 记录 h3→h1 的请求，优先级 10 表项的直接计数器记录 h1→h3 的应答。先用 `ip netns list` 查看本次命名空间名称，再按脚本打印的命令进入对应主机。

脚本也会打印实际命名空间、抓包和 ping 命令。`--keep` 模式下用 Ctrl+C 结束，手工启动的抓包程序应先停止。正常结束、报错、SIGINT 或 SIGTERM 时，脚本清理本次创建的接口、命名空间、BMv2 进程和临时目录。需要保留日志时，请在退出前复制打印的临时目录。

## 练习

- 将固定默认动作改成 `deny()`，重新编译，并显式配置需要允许的方向。同步修改验证用例，区分默认拒绝与显式拒绝表项的计数。
- 增加 TCP flags 匹配，观察 SYN、ACK 等报文的处理。flags 匹配检查的是当前报文字段，判断连接是否已建立还需要结合双向报文与历史状态。
- 尝试用 `register` 保存连接状态，为双向五元组定义映射关系，并明确握手状态变化、超时回收和并发更新规则。

实测环境：Ubuntu 24.04 / WSL2，p4c `1.2.5.10`、BMv2 `1.15.0-2bdd0b7b`、Python `3.12.3`。
