# 示例 02 · L2 静态转发交换机

本例在 BMv2 `simple_switch` 上按目的 MAC 转发以太帧。已配置的单播地址对应一个输出端口，未知目的地址通过多播组泛洪到其他端口，以太网头与负载保持不变。目的 MAC 表项和多播组由控制平面预先配置。

表与流水线的说明见[第 8 章](../../docs/08-匹配动作表.md)和[第 11 章](../../docs/11-V1Model架构.md)，工具使用见[第 14 章](../../docs/14-BMv2编译与运行.md)。

## 拓扑与依赖

```text
h1 (10.0.0.1/24) ── 端口 1 ──┐
h2 (10.0.0.2/24) ── 端口 2 ──┼── s1：l2_switch.p4
h3 (10.0.0.3/24) ── 端口 3 ──┘
```

主机 MAC 依次为 `00:00:00:00:00:01`、`00:00:00:00:00:02`、`00:00:00:00:00:03`，各自位于独立的 network namespace 中，经 veth 接入交换机。主机侧接口均为 `eth0`，`run.sh` 在每次运行时生成命名空间与交换机侧接口名，并创建相应资源。

需要 `p4c-bm2-ss`、`simple_switch`、`simple_switch_CLI`、`ip`、`ping`、`timeout`，以及支持 `os.setns` 的 Linux Python 3.12+。逐帧验证只使用 Python 标准库。手工抓包另需 `tcpdump`。环境安装见[第 1 章](../../docs/01-环境搭建.md)。

## 转发与泛洪

1. Parser 提取 14 字节以太网头。Ingress 检查 `parser_error` 和报头有效位，解析失败时显式丢弃。
2. `dmac` 表按目的 MAC 精确匹配。`forward(port)` 选择单播端口，默认动作 `broadcast(1)` 选择多播组 1。
3. 控制平面将组 1 配置为端口 1、2、3。复制后，每份报文进入 Egress。`egress_port == ingress_port` 的副本被丢弃，其余副本发往各自端口。

组 1 的端口列表包含入端口，回源副本由 Egress 过滤。相同判断也适用于普通单播：若目的 MAC 对应入端口，该帧会被丢弃。

未知单播泛洪时保留原目的 MAC。命令文件还将广播地址 `ff:ff:ff:ff:ff:ff` 显式映射到组 1，ARP 请求通过这条表项泛洪。其他未配置的组播目的地址也走默认泛洪，当前配置将三个端口置于同一广播域。

IPv4、ARP 等内容作为未解析的负载，由 BMv2 随以太网头原样输出。两个校验和控制块为空，程序按二层字节转发。报文复制与 Egress 的处理顺序见 [11.5.8 节](../../docs/11-V1Model架构.md#1158-多种请求同时出现时)。

## 编译与运行

以下命令从**仓库根目录**执行，分别用于单独编译和运行完整实验：

```bash
bash examples/02-l2-switch/build.sh
sudo bash examples/02-l2-switch/run.sh
```

`build.sh` 默认生成示例目录下的 `l2_switch.json` 和 `l2_switch.p4info.txtpb`，也可用第一个参数指定输出目录。此次实验通过 Thrift CLI 配置，P4Info 仅供查看。

`run.sh` 自动将当前源码编译到临时目录，再创建拓扑、启动交换机、等待 Thrift 服务、加载配置并验证转发。默认验证通过后退出并清理资源，编译、启动、配置或验证失败时返回非零状态。

默认使用 Thrift 端口 9090。若该端口已占用，脚本在创建拓扑前退出。可为本次实例另选空闲端口：

```bash
sudo env P4_L2_THRIFT_PORT=9091 bash examples/02-l2-switch/run.sh
```

## 配置文件的使用条件

[runtime/s1-commands.txt](./runtime/s1-commands.txt)用于刚启动、尚未配置过的交换机。它建立组 1 和一个包含端口 1、2、3 的复制节点，再写入四条目的 MAC 表项，最后用 `table_dump`、`mc_dump` 读回配置。

```text
mc_mgrp_create 1
mc_node_create 0 1 2 3
mc_node_associate 1 0
```

`mc_node_create` 的第一个参数是 RID，用于为副本填写 `egress_rid`。命令另行返回**节点句柄**，供 `mc_node_associate` 的第二个参数引用。本机新实例的首个节点返回句柄 0，命令文件按这个条件编写。已有配置时，使用实际返回的句柄关联或修改复制节点。

本机 CLI 将 `#` 行视为命令，空行会重复上一条命令。`run.sh` 先过滤整行注释和空行，再加载配置并检查错误文本。手工加载时同样先过滤，配置结果结合逐条输出、`table_dump`、`mc_dump` 和报文验证核对。

## 自动验证

[verify.py](./verify.py)从三台主机发送带随机标识的测试帧，排除本机发包记录，逐字节比较接收内容并统计每个端口的副本数：

| 检查                | 输入与预期结果                                                         |
| ------------------- | ---------------------------------------------------------------------- |
| 静态单播，共 18 帧  | 六个有向主机对，各发送 60、128、1514 字节帧。只有目的主机收到一份      |
| 同端口过滤，共 3 帧 | 各主机发送目的 MAC 为自身地址的帧。三个端口均不输出                    |
| 未知单播，共 3 帧   | 各主机发送目的 MAC 为 `02:00:00:00:00:99` 的帧。另外两台主机各收到一份 |
| 广播，共 3 帧       | 各主机发送广播帧。另外两台主机各收到一份                               |

帧长不含 FCS。需要接收的用例最多等待 3 秒，收到全部预期副本后再观察 0.3 秒。预期丢弃的用例观察 0.3 秒。超时、内容变化、错误端口或重复副本都会使验证失败。

随后 `run.sh` 执行 h1→h2、h2→h3、h3→h1 的 ping，每对发送两次请求。主机通过 ARP 解析邻居，任何一组 ping 失败都会令脚本报错。全部通过后输出：

```text
PASS：L2 单播、泛洪、回源抑制和三对主机 ping 验证完成
```

## 手工观察与清理

```bash
sudo bash examples/02-l2-switch/run.sh --keep
```

自动验证通过后保留拓扑。脚本打印本次实例的命名空间、抓包与 ping 命令、CLI 连接端口、重新验证命令及日志路径。在 CLI 中可用 `table_dump MyIngress.dmac`、`mc_dump` 检查实际配置。

观察 ARP 时，按脚本打印的接收方向命令抓包，将命名空间替换为 h1、h2、h3 各自的实际名称。再在 h1 的命名空间中执行 `ip neigh del 10.0.0.2 dev eth0` 并向 h2 发 ping。h2、h3 应收到广播请求，h2 的单播应答返回 h1。清除邻居项用于触发一次新的 ARP 解析。

正常退出、错误、SIGINT 或 SIGTERM 时，脚本停止自己启动的 BMv2，并清理本次记录的接口、命名空间和临时目录。`--keep` 模式下用 Ctrl+C 结束。手工启动的抓包程序应先停止。需要保留 JSON、P4Info 或日志时，在退出前复制临时目录中的文件。

## 练习与适用范围

- 增加显式丢弃表项，验证它只影响对应目的 MAC，且不会被默认泛洪覆盖。
- 实现 MAC 学习时，结合[第 15 章](../../docs/15-P4Runtime控制平面.md#157-典型模式l2-学习)增加源地址上报、控制器接收、表项更新与老化。
- 按 VLAN 隔离广播域时，增加标签解析与有效性检查，将 VLAN 纳入匹配键，并为各 VLAN 配置多播组。

若希望在复制前排除入端口，可以由控制平面配置不同的端口集合，再在 Ingress 按入端口选择对应多播组。复制后的 `egress_rid` 由节点的 RID 填写，在 Egress 中读取。

实测环境：Ubuntu 24.04 / WSL2，p4c `1.2.5.10`、BMv2 `1.15.0-2bdd0b7b`、Python `3.12.3`。
