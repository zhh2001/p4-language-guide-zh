# 04 · 语法基础

本章介绍 P4<sub>16</sub> 的预处理、字面量、表达式、语句和参数传递，语言规则以 P4<sub>16</sub> 规范 v1.2.5 为依据。

除特别说明外，代码块都是语法片段。类型和函数声明放在相应的声明区域，赋值、分支与调用放在函数体、动作体或 `control` 的 `apply` 块等允许的位置。涉及 `hdr`、`meta` 或表的片段，需要补齐对应声明，编译方法见 4.16 节。

## 4.1 预处理器

P4 源码可以在语法分析前经过预处理。规范规定编译器应支持的 C 预处理功能子集包括：

- `#define`（不带参数的宏）与 `#undef`。
- `#if`、`#else`、`#endif`、`#ifdef`、`#ifndef`、`#elif`。
- `#include`。

带参数的宏等额外功能取决于工具链。p4c 可以调用外部预处理器完成预处理。

```p4
#include <core.p4>
#include <v1model.p4>
```

尖括号形式通常用于工具链提供的头文件，双引号形式如 `#include "headers.p4"` 常用于项目自身的文件。两者的区别是文件搜索顺序，具体搜索路径由预处理器及 `-I` 选项等配置决定。

规范要求程序包含核心库。`core.p4` 定义 `packet_in`、`packet_out`、`NoAction` 和 `exact`、`ternary`、`lpm` 等基础声明。它可以直接包含，也可以由架构文件间接包含。本教程的完整示例显式包含它，以便说明依赖。

## 4.2 标识符与保留字

标识符区分大小写，使用 ASCII 字母、数字和下划线，首字符不能是数字。单独的 `_` 是特殊记号，在允许的上下文中表示“不关心”，不能当作普通变量名。

`action`、`bit`、`control`、`if`、`parser`、`return`、`switch` 等是语言关键字。完整列表见规范附录 B。部分词在语法允许的位置仍可作为名字，例如 `apply`、`state`、`type`。表属性中的 `key`、`actions` 等也有上下文限制。为变量和类型命名时，宜避开这些名字及核心库已有的名字。

```p4
const bit<16> ETHERTYPE_IPV4 = 0x0800;
typedef bit<9> PortId_t;
```

## 4.3 命名约定

规范示例采用以下约定。这些是书写风格，不是编译器强制执行的规则。

| 元素                 | 规范示例中的风格 | 例子                |
| -------------------- | ---------------- | ------------------- |
| 内置类型             | 小写             | `int<16>`           |
| 自定义类型           | 首字母大写       | `IPv4Address`       |
| 类型参数             | 大写             | `parser P<H, IH>()` |
| 变量                 | 首字母小写       | `ipv4header`        |
| 常量                 | 大写             | `CPU_PORT`          |
| `error`、`enum` 成员 | 驼峰             | `PacketTooShort`    |

本教程还使用 `ethernet_t`、`headers`、`meta` 等名称，同一份程序中的命名风格应保持一致。

## 4.4 注释

```p4
// 单行注释

/* 跨越多行的
   注释 */
```

块注释不能嵌套。注释也是记号之间的分隔符：`bi/**/t` 不会被拼成关键字 `bit`。

## 4.5 字面量

### 4.5.1 布尔

布尔字面量只有 `true` 和 `false`，类型为 `bool`。整数 `0`、`1` 不会自动变成布尔值。

### 4.5.2 整数字面量

整数字面量可以指定进制、位宽和符号性。

| 进制前缀     | 含义     |
| ------------ | -------- |
| `0x` 或 `0X` | 十六进制 |
| `0o` 或 `0O` | 八进制   |
| `0d` 或 `0D` | 十进制   |
| `0b` 或 `0B` | 二进制   |
| 无           | 十进制   |

没有进制前缀时，带前导零的数仍按十进制解释。例如，`0377` 的值是十进制 377，`0o377` 的值才是十进制 255。

在数值前加 `Nw`，得到 `bit<N>` 类型，加 `Ns` 则得到 `int<N>` 类型。不指定这一前缀时，字面量的类型是任意精度整数 `int`。这里的 `int` 用于编译期计算，不是默认的 32 位运行时整数。

```p4
const bit<16> etherType = 16w0x0800; // 值为 2048
const bit<8>  pattern = 8w0b1010_1010; // 值为 170
const int<8>  signedPattern = 8s0b1010_1010; // 同一位模式，值为 -86
const bit<16> decimalValue = 16w0377; // 值为 377
const bit<16> octalValue = 16w0o377; // 值为 255
const int    wideConstant = 1 << 80; // 编译期的任意精度整数
```

`int<N>` 使用二进制补码。负号属于一元运算符，例如 `-8s1` 表示对有符号字面量 `8s1` 取负。本机 p4c 对上例的 `8s0b1010_1010` 会报告溢出警告，得到的值仍为 -86。若只需表达这个数值，可写成 `-8s86`。

### 4.5.3 下划线分隔符

下划线可以分隔数值部分的数字，计算数值时会被忽略，但不能用于位宽前缀，也不能作为整个整数字面量的首字符。

```p4
const bit<48> MAC = 48w0x02_00_00_00_00_01;
```

字面量内部不能插入空格或注释。`48w0x02_00` 是一个记号，`48 w 0x0200` 则不是。

### 4.5.4 字符串

字符串用双引号包围，可以用 `\"` 在字符串中写入双引号。其他转义序列的具体解释由使用该字符串的工具决定。

```p4
const string CHECK_MESSAGE = "PORT_BITS must be 9";
const int PORT_BITS = 9;
const bool PORT_BITS_OK = static_assert(PORT_BITS == 9, CHECK_MESSAGE);
```

`string` 用于编译期已知的字符串，不能用作运行时变量类型。它常用于注解 `@name("ipv4_route")` 和核心库的 `static_assert(条件, 消息)`。字符串类型的参数必须无方向，`static_assert` 的条件和消息也必须在编译期已知。

## 4.6 运算符速查

下表列出常见运算符及其适用条件。

| 类别                 | 运算符或形式                | 要点                                                      |
| -------------------- | --------------------------- | --------------------------------------------------------- |
| 算术                 | `+` `-` `*`                 | 固定位宽运算不会自动扩大结果位宽                          |
| 编译期整数除法、取余 | `/` `%`                     | 用于任意精度 `int` 的常量计算，操作数须非负，除数不能为零 |
| 饱和算术             | `\|+\|` `\|-\|`             | 超出类型范围时停在边界，具体支持取决于目标                |
| 位运算               | `&` `\|` `^` `~` `<<` `>>`  | 注意位宽、符号性及移位量类型                              |
| 比较                 | `==` `!=` `<` `<=` `>` `>=` | 结果为 `bool`，可用形式取决于操作数类型                   |
| 逻辑                 | `&&` `\|\|` `!`             | 操作数为 `bool`，`&&`、`\|\|` 采用短路求值                |
| 位串拼接             | `++`                        | 左操作数放在高位                                          |
| 位切片               | `[H:L]`                     | 取闭区间 `[L, H]`                                         |
| 条件                 | `? :`                       | 条件须为 `bool`，两分支须满足类型匹配规则                 |
| 掩码、范围           | `&&&` `..`                  | 用于集合匹配，如 Parser 的 `select` 标签                  |

例如，`8w255 + 8w1` 的结果是 `8w0`，而 `8w255 |+| 8w1` 的结果是 `8w255`。乘法等运算能否映射到目标，由编译器后端检查。

v1.2.5 没有浮点类型、C 风格的自增/自减或逗号表达式，赋值语句也没有 `+=` 等复合形式。本机 p4c 1.2.5.10 能编译 `x += 1`，超出了这一版本规定的赋值语法。本章按 v1.2.5 写成 `x = x + 1`。

### 4.6.1 位切片

```p4
bit<32> address = 0xC0000201;
bit<8> firstByte = address[31:24];  // 0xC0
bit<8> secondByte = address[23:16]; // 0x00
```

最低位编号为 0，高位索引写在前面。对于 `bit<W>`，须满足 `0 <= L <= H < W`，边界必须是局部编译期已知的值，结果类型为 `bit<H-L+1>`。对 `int<W>` 切片时，结果也为无符号位串。

### 4.6.2 位串拼接

```p4
bit<16> high = 0x1234;
bit<8> low = 0x56;
bit<24> combined = high ++ low; // 0x123456
```

拼接结果的位宽是两个操作数位宽之和，符号性与左操作数相同。这里两个操作数都是无符号数，因此结果是 `bit<24>`。

## 4.7 语句

赋值、方法调用、`return` 和 `exit` 等语句以分号结束。块语句、`if` 和 `switch` 的右花括号后不要求再加分号。不同程序块允许的语句和调用不同。

### 4.7.1 赋值

```p4
bit<8> ttl = 64;
ttl = ttl - 1;
```

赋值左侧必须是可写的左值，例如变量、可写字段或位切片。常量、`in` 参数和普通算术表达式不能放在左侧。赋值还必须满足类型匹配规则，见 4.15 节。

extern 对象不能通过赋值复制，应通过它提供的方法访问。

### 4.7.2 块语句

```p4
{
    bit<8> temporary = 1;
    temporary = temporary + 1;
}
```

块内声明的名字只在其作用域内可见。跨报文保存数据需要架构提供的 Register 等有状态 extern，普通局部变量不承担这一用途。

### 4.7.3 空语句

单独的 `;` 是空语句，不执行操作。

### 4.7.4 条件语句

下面假设 `ttl` 为 `bit<8>`，`expired` 为可写的 `bool`：

```p4
if (ttl <= 1) {
    expired = true;
} else {
    ttl = ttl - 1;
    expired = false;
}
```

条件必须为 `bool`。若 `ttl` 是整数，`if (ttl)` 不合法，应按意图写成 `if (ttl != 0)` 等布尔表达式。例中的 `expired` 只是一个标记，实际丢包还要执行架构规定的操作。

### 4.7.5 `switch` 语句

按 v1.2.5 第 12.7 节的规定，`switch` 用于控制块中。本章示例均放在 `control` 的 `apply` 块中，分为两种用法。

**根据表执行的动作分支。** 假设 `ipv4_lpm` 的动作列表中包含 `forward` 和 `drop`：

```p4
switch (ipv4_lpm.apply().action_run) {
    forward: { /* 执行 forward 后的处理 */ }
    drop:    { /* 执行 drop 后的处理 */ }
    default: { /* 执行其他动作后的处理 */ }
}
```

`apply()` 先执行查表及所选动作，随后根据动作名进入分支。如果未命中时执行的默认动作是 `drop`，这里进入的就是 `drop` 分支。`switch` 的 `default` 标签匹配前面未列出的动作，判断表是否命中则使用 `table.apply().hit` 或 `.miss`。每次调用 `apply()` 都会重新执行查表和动作。

如果表执行的动作调用了 `exit`，后面的 `switch` 分支也不会执行。

**根据整数、枚举或 `error` 分支。** 下面假设 `etherType` 为 `bit<16>`，用布尔变量记录是否为 IP 报文：

```p4
bool isIp = false;
switch (etherType) {
    0x0800:
    0x86DD: { isIp = true; }
    default: { isIp = false; }
}
```

普通 `switch` 的表达式可以是 `bit<W>`、`int<W>`、`enum` 或 `error`。除 `default` 外，标签必须是类型相容的编译期常量，不能重复。`default` 可省略，若存在则必须放在最后。

标签后没有块时，与下一标签共用后续的块。执行完一个块后就离开 `switch`，不需要 C 的 `break`。上例中 IPv4 和 IPv6 共用同一段赋值。报头解析分支使用 Parser 的 `transition select`，见 4.7.8 节。

### 4.7.6 `return`

- 在动作或控制块的 `apply` 中，`return;` 结束当前动作或当前控制块，调用者随后继续执行。
- 在返回类型为 `void` 的函数中使用 `return;`，有返回值的函数使用 `return 表达式;`。
- Parser 不允许 `return`，应使用状态转移结束解析。

返回时仍会执行 `out`、`inout` 参数的复制出。

### 4.7.7 `exit`

`exit;` 终止当前正在执行的动作、控制块及其调用链上仍在执行的动作和控制块。它不能用于 Parser 或函数体，退出时仍须完成相应参数的复制出。

本机编译器在嵌套动作的 `exit` 与参数写回组合上存在实现偏差，复现现象和处理方法见 [7.10 节](./07-控制块与动作.md#710-exit-与-return)。

`exit` 结束的是当前控制流，报文去向仍由元数据和架构规则决定。例如，在 V1Model 的 Ingress 中执行 `exit` 后，报文若按元数据进入 Egress，仍会执行该阶段。

### 4.7.8 `transition`（Parser 专属）

下面是 Parser 中的一个状态，假设相应报头与 `parse_ipv4` 状态已经声明：

```p4
state parse_ethernet {
    packet.extract(hdr.ethernet);
    transition select(hdr.ethernet.etherType) {
        0x0800: parse_ipv4;
        default: accept;
    }
}
```

状态名后面没有函数调用的括号。`accept` 表示解析成功结束，详情见 [第 6 章](./06-Parser解析器.md)。

## 4.8 参数方向修饰符

P4 的普通值参数采用 **复制入/复制出（copy-in/copy-out）** 语义。完整调用规则见规范[第 6.8 节](https://p4.org/wp-content/uploads/sites/53/2024/10/P4-16-spec-v1.2.5.html#sec-calling-convention)。

| 方向    | 进入调用时                     | 返回时                   |
| ------- | ------------------------------ | ------------------------ |
| `in`    | 复制实参的值，形参只读         | 不写回                   |
| `out`   | 不复制实参的原值               | 将形参结果复制回实参位置 |
| `inout` | 复制实参的值，形参可读写       | 将形参结果复制回实参位置 |
| 无方向  | 含义取决于被调用的构造，见下文 | 普通值参数不写回         |

`out` 形参的初始化取决于类型：普通整数的初值没有保证，报头、报头联合等则按规则初始化为无效。程序应在读取普通 `out` 值之前赋值，并在需要输出的执行路径上写入结果。

复制语义在两个参数使用同一个实参时尤其明显。以下函数声明放在顶层：

```p4
void update(inout bit<8> first, inout bit<8> second) {
    first = 1;
    second = second + 1;
}
```

在调用位置执行：

```p4
bit<8> value = 5;
update(value, value); // 返回后 value 为 6
```

两个形参进入函数时各自得到 5。修改 `first` 不会改变 `second`。返回时按实参在调用中出现的顺序复制出，后写回的 6 覆盖先写回的 1。本机 p4c 会对这处输出实参重叠给出 `ordering` 警告。

无方向参数的含义取决于调用场景。构造参数要求在编译期确定，非动作的无方向值参数也要求实参在编译期已知。动作的无方向参数表示动作数据：表执行动作时由表项或默认动作提供，直接调用动作时也可由数据平面的表达式提供。

无方向的 extern 对象参数按引用传递，对象本身不可复制。

### 默认参数值

只有 `in` 和无方向参数允许默认值，默认表达式必须在编译期已知。下面是 extern 函数声明及一个使用它的顶层函数，`f` 的实现需要目标提供：

```p4
extern void f(in bit<1> a, in bit<3> b = 2, in bit<5> c);

void call_f() {
    f(a = 1, b = 2, c = 3);
    f(a = 1, c = 3); // b 使用默认值
    f(1, 2, 3);
    // f(1, 3);     // 错误：3 对应 b，必需的 c 仍然缺失
}
```

省略中间位置的默认参数时，应使用具名实参。

### 可选参数 `@optional`

`@optional` 表示调用时可以省略实参，省略后的行为由架构或外部实现规定。它可用于包、Parser/Control 类型、extern 函数、方法及构造函数的参数。

下面是架构接口的示意，`Pipeline` 的参数被简化为空：

```p4
package Pipeline();
package Switch(Pipeline first, @optional Pipeline second);

Pipeline() ingress;
Switch(ingress) main;
```

这段自定义包声明可用 `p4test` 检查，运行则需要相应的架构实现。同一个参数不能同时使用 `@optional` 和默认值。一个参数列表若同时含有可选参数和带默认值的参数，调用时必须使用具名实参。

## 4.9 尾随逗号

枚举成员等部分列表允许在最后一项后保留逗号：

```p4
enum Protocol {
    IPv4,
    IPv6,
}
```

枚举成员的尾随逗号便于与条件预处理结合。v1.2.5 的函数参数列表和调用实参列表不接受尾随逗号，例如 `f(1, 2, 3,)` 不合法。

## 4.10 名称解析

名字通常从当前作用域向外层查找。P4 还有顶层匿名命名空间，`.名字` 可以明确引用顶层声明：

```p4
const bit<32> increment = 2;

control AddIncrement(inout bit<32> result) {
    bit<32> increment = 1;
    apply {
        result = increment + .increment; // 1 + 2
    }
}
```

这里 `increment` 指局部声明，值为 1，`.increment` 指顶层常量，值为 2。

## 4.11 函数调用

以这个 extern 函数声明为例：

```p4
extern void read_value(in bit<32> index, out bit<16> value);
```

以下片段放在目标允许调用该 extern 的执行位置：

```p4
bit<32> index = 0;
bit<16> value;
read_value(index, value);               // 按位置
read_value(index = index, value = value); // 按名称
read_value(value = value, index = index); // 具名实参可调整顺序
```

一次调用要么全部按位置，要么全部按名称，不能混用。具名实参等号左边是形参名，右边是调用者提供的表达式。

以下调用会被编译器拒绝：

```p4
read_value(index = index, value); // 错误：混用两种形式
read_value(index = index);        // 错误：缺少必需参数
read_value(index = index, value = 0); // 错误：0 不是可写的左值
```

`out` 和 `inout` 实参需要可写左值。不需要某个 `out` 结果时，可以传入 `_`。

## 4.12 函数声明

用户定义函数在顶层声明，函数体由 P4 代码实现。extern 函数只声明接口，实现由目标提供。本章函数示例显式标注每个运行时参数的方向：

```p4
bit<32> max_value(in bit<32> left, in bit<32> right) {
    return (left > right) ? left : right;
}
```

非 `void` 函数必须在所有可能的执行路径上返回类型相容的值。P4 不允许直接或间接递归。

## 4.13 常量声明

```p4
const bit<16> ETHERTYPE_IPV6 = 0x86DD;

struct Version {
    bit<8> major;
    bit<8> minor;
}
const Version VERSION = { 1, 0 };
```

常量必须在声明时初始化，之后不能赋值。其初值须是局部编译期已知的表达式，可见范围由声明所在的作用域决定。“局部编译期已知”与一般“编译期已知”的区别见规范第 18.1 节。

## 4.14 `typedef` 与 `type`

```p4
typedef bit<32> IPv4Addr; // 原类型的别名
type bit<32> NodeId;     // 与原类型不同的新类型
```

`typedef` 不建立类型隔离，`IPv4Addr` 和 `bit<32>` 可以互换。`type` 建立新类型，不能把已有的底层类型值直接当作新类型值使用：

```p4
bit<32> raw = 7;
NodeId node = (NodeId)raw;
bit<32> restored = (bit<32>)node;
```

对 `NodeId` 做加法时，先转成 `bit<32>` 运算，再转回 `NodeId`。这种新类型适合区分端口号、节点编号等用途不同但位宽相同的数据，具体支持的底层类型见 [第 5 章](./05-类型系统.md)。

## 4.15 显式与隐式类型转换

### 数值表达式中的隐式转换

常见的两类规则是：任意精度整数 `int` 转为上下文要求的固定位宽整数，以及带底层类型的枚举转为其底层类型。例如，`x` 为 `bit<8>` 时，`x + 1` 会把 `1` 转为 `bit<8>`。

不同位宽的运行时整数之间需要显式转换，例如 `bit<8>` 与 `bit<16>` 相加时应先统一类型。整数与 `bool` 也不会自动互换。转换后的常量若超出范围，还可能产生截断和编译器警告。

### 常见显式转换规则

显式转换写成 `(目标类型)表达式`。

| 源 → 目标                    | 行为                                            |
| ---------------------------- | ----------------------------------------------- |
| `bit<1>` ↔ `bool`            | 0 对应 `false`，1 对应 `true`                   |
| `int` → `bool`               | 仅允许值 0 或 1                                 |
| `int<W>` ↔ `bit<W>`          | 保持位模式，改变有符号/无符号解释              |
| `bit<W>` → `bit<X>`          | 缩窄时保留低位，扩宽时补零                      |
| `int<W>` → `int<X>`          | 缩窄时保留低位，扩宽时复制符号位                |
| 固定位宽整数 → `int`         | 保持数值，结果用于编译期计算                    |
| `int` → `bit<W>` 或 `int<W>` | 按目标位宽保留补码的低 W 位，再按目标符号性解释 |
| `type` 新类型 ↔ 原类型       | 显式转换，不自动获得其他类型间的转换规则        |

例如，将 `8w255` 转为 `int<8>` 得到 -1，先扩成 `bit<16>`，再转成 `int<16>` 才得到正数 255。

### 常见类型错误

假设 `x`、`y`、`z` 分别为已赋值的 `bit<8>`、`bit<16>`、`int<8>` 运行时变量：

| 表达式      | 问题                                             | 一种可编译的改写                      |
| ----------- | ------------------------------------------------ | ------------------------------------- |
| `x + y`     | 位宽不同                                         | `(bit<16>)x + y`                      |
| `x + z`     | 符号性不同                                       | `x + (bit<8>)z`                       |
| `(int<8>)y` | 一次转换同时改变位宽和符号性                     | `(int<8>)(bit<8>)y`                   |
| `y + z`     | 位宽和符号性都不同                               | `(int<18>)(bit<18>)y + (int<18>)z`    |
| `x << z`    | 运行时移位量为有符号类型                         | 确认 `z >= 0` 后使用 `x << (bit<8>)z` |
| `1 << x`    | 任意精度整数作为左操作数，移位量却在运行时才知道 | `32w1 << x`                           |
| `~1`        | 按位取反缺少确定的位宽                           | `~32w1`                               |

`x + (bit<8>)z` 会把负数 `z` 解释为无符号位模式，对 `y` 先缩窄再转为有符号数可能丢掉高位。`y + z` 的示例则先扩宽并保留两个操作数的数值，18 位有符号结果可以容纳其完整和的范围 `[-128, 65662]`。

对有符号移位量，应先处理负数输入，再将非负值转成无符号类型。`1 << 3` 完全在编译期计算，是合法表达式。

## 4.16 编译检查与本章小结

检查片段时，应先补齐声明并放入完整程序。可以复制 [Hello P4](../examples/01-hello/hello.p4) 为 `syntax-check.p4`，将普通值的运算片段放入 Ingress 的 `apply`，将函数和类型声明放在顶层，再从该副本所在目录执行：

```bash
p4test --std p4-16 syntax-check.p4
p4c-bm2-ss --std p4-16 --arch v1model \
    -o /tmp/syntax-check.json syntax-check.p4
```

`p4test` 用于前端及中间处理检查，BMv2 后端还会检查目标能否实现这份程序。涉及自定义 extern 或架构包的片段，可先用 `p4test` 检查语言规则，运行时需有对应的目标实现。

阅读代码时，先确认表达式的类型和位宽，再判断语句所处的上下文。尤其注意参数是否复制回调用者、分支依据是表命中还是动作名，以及转换是否改变数值。
